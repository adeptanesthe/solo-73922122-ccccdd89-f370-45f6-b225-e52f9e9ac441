# 高温炉温度实验工具（GP 采样选点 + 突变归因）

同一个网页里的两个工具，都基于**共享的平方指数核高斯过程（GP）**：

1. **采样选点**：为炉温实验选择 2 个新增采样时刻，使全部候选时刻的总后验方差下降最大；
2. **突变归因**：炉温曲线突然跳变时，判断该查温控（两支探头共同阶跃）还是查探头
   （仅待检探头阶跃），并在判为阶跃时给出最可能的阶跃时刻。

```
docker compose up --build      # 打开 http://localhost:8000
```

---

## 一、采样选点

### 数学原理

- 核函数（平方指数）：`k(x, x') = signal_variance · exp(-(x-x')² / (2ℓ²))`
- 观测模型：`y = f(x) + ε`，`ε ~ N(0, σ_n²)`
- 已测数据下的后验协方差：`Σ = K_cc − K_co (K_oo + σ_n²I)⁻¹ K_oc`
- 若在点对 `p = {i, j}` 补充观测：`Σ' = Σ − A (B + σ_n²I)⁻¹ Aᵀ`，
  其中 `A = Σ[:, p]`，`B = Σ[p, p]`
- 目标：最大化总方差下降 `Δ(p) = tr(Σ − Σ') = tr((B + σ_n²I)⁻¹ AᵀA)`，
  枚举所有合法点对取最大（`app/gp.py` 中做了 O(m²) 向量化）

温度观测值只影响后验均值，不影响后验方差，因此选点无需预知未来的测量值；
页面同时展示选点前的后验均值曲线 ±2σ 供参考。

### 合法性与整批拒绝

合法点对需同时满足：两点都不是已测时刻（容差：相对 1e-9 / 绝对 1e-12）；
两点不重复；间隔 ≥ 最小时间间隔；点对协方差矩阵非数值退化。

以下情况**整批拒绝**（HTTP 422，不返回任何部分建议）：

| 情形 | detail.code |
|---|---|
| 输入含 NaN / Inf、参数越界、字段缺失 | `INVALID_INPUT` / `NON_FINITE_INPUT` |
| 观测核矩阵非正定（含数值近奇异） | `KERNEL_NOT_PSD` |
| 不存在合法候选点对 | `NO_FEASIBLE_COMBINATION` |

## 二、炉温突变归因

### 使用方式

1. 「已测数据」一栏（也就是选点用的数据）作为**参考探头记录**；
2. 在「突变归因」页填写**待检探头**的时刻与读数；
3. 填写 1–20 个**互不相同**的可疑阶跃时刻；
4. 填写**阶跃幅度的先验标准差**（零均值高斯先验）；
5. 核长度尺度、观测噪声、核信号方差与选点共用同一组参数。

### 模型

两支探头共享同一个 GP：`f ~ GP(0, k_SE)`；两个探头**每条读数的高斯噪声独立**，
标准差同为表单里的 `noise_std`（归因要求 **> 0**）。三类**等先验**假设：

| 假设 | 含义 |
|---|---|
| `no_step` | 无阶跃（两支探头都跟随同一个 GP） |
| `common_step` | 两支探头从可疑时刻 τ 起**共同**出现同一幅度的阶跃（温控侧问题） |
| `test_probe_step` | **仅待检探头**从 τ 起出现阶跃（探头侧问题） |

- 阶跃从候选时刻 τ 起生效（**含 τ**）；
- 幅度 `A ~ N(0, step_prior_std²)`，与 GP 一起被积分掉，观测的边际协方差为
  `C = K + σ_n²I + s²·v vᵀ`（`v` 为“从 τ 起”的 0/1 指示向量，`s = step_prior_std`），
  因此每类假设的边际似然可闭式求值；
- **有效时刻**：候选时刻必须有两支探头各自的读数作证——阶跃前和从该时刻起**各至少一条**
  （恰好等于 τ 的读数算“从该时刻起”）；
- 每类阶跃的**时刻先验在有效时刻间均分**（`1/n_valid`），三类假设先验各 `1/3`；
- 三类后验概率由边际似然归一化得到；**最高后验 ≥ 90%** 才下结论，否则提示**待复核**；
- 判为某类阶跃时，给出该类内**时刻后验最大**的候选时刻及其时刻后验概率；
- 没有有效时刻或数值求解失败时，整批拒绝并说明原因；没有有效时刻时还会附带
  每个可疑时刻的取证诊断（各侧读数条数、缺失原因）。

### 归因 API 与拒绝码

`POST /api/attribute`：

```json
{
  "reference_times": [0, 1, 2, 3, 5, 8, 13],
  "reference_values": [25.3, 196.1, 330.8, 433.5, 578.2, 695.1, 769.9],
  "test_times": [0, 1, 2, 3, 5, 8, 13],
  "test_values": [22.1, 201.5, 336.0, 428.7, 972.4, 1091.0, 1168.3],
  "suspicious_times": [3, 5, 8, 10],
  "length_scale": 2.0,
  "noise_std": 5.0,
  "signal_variance": 100000.0,
  "step_prior_std": 400.0
}
```

响应：`posterior_probabilities`（三类）、`decision`、`conclusive`、`threshold`、
`best_step_time`、`best_step_time_probability`、`n_valid_step_times`，以及每个可疑时刻的
`valid / reason / reference_before / reference_after / test_before / test_after /
log_likelihood_common / log_likelihood_test_probe / time_weight_common / time_weight_test_probe`。
上面的示例数据判为「仅待检探头阶跃」，最可能时刻 t = 5。

| 情形 | detail.code |
|---|---|
| 数值非法 / 长度不一致 / 可疑时刻为空、重复或超过 20 个 / 噪声 ≤ 0 | `INVALID_INPUT` |
| 输入含 NaN / Inf | `NON_FINITE_INPUT` |
| 观测核矩阵非正定或数值近奇异 | `KERNEL_NOT_PSD` |
| 没有有效候选时刻（detail 附带 `candidates` 诊断） | `NO_VALID_STEP_TIME` |
| 数值求解失败（如阶跃方向退化） | `SOLUTION_FAILED` |

### 前端行为

- 归因输入（参考/待检读数、可疑时刻、阶跃先验、模型参数）**一有改动就撤下旧结果**；
- 每次提交都带代际编号，**早先请求的迟到响应不会回填**（也不会改动按钮/提示状态）；
- 三类后验概率用条形图展示并标注 90% 阈值线；未达阈值时只提示待复核、不给时刻结论；
- 无有效时刻时展示错误原因与逐时刻取证明细表。

## 三、运行

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

容器内固定 `OPENBLAS_NUM_THREADS=1` / `OMP_NUM_THREADS=1`：本案矩阵规模（≤ 2000×2000）
下单线程 BLAS 反而快得多，也避免线程超额订阅。compose 带有 `/api/health` 健康检查。

### 本地运行

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
OPENBLAS_NUM_THREADS=1 uvicorn app.main:app --host 0.0.0.0 --port 8000
# 打开 http://localhost:8000
```

### 网页使用

- 「采样选点」页：粘贴/导入已测数据、候选时刻，填参数后点「计算选点」；
  展示选中时刻、总方差前后对比、后验均值 ±2σ、逐候选点方差明细；
- 「突变归因」页：已测数据自动作为参考探头，填待检读数与可疑时刻后点「计算归因」；
- 「采样选点」页有「载入示例数据」；「突变归因」页有「载入归因示例」，会填好
  共享的已测数据、待检读数、可疑时刻、阶跃先验与模型参数。该示例判为
  「仅待检探头阶跃」，最可能时刻 t = 5。

## 四、API 概览

- `POST /api/select`：选点（请求/响应字段见选点一节与 `/docs`）；
- `POST /api/attribute`：突变归因（见上）；
- `GET /api/health`；交互式文档 `/docs`。

规模上限：每支探头读数 ≤ 1000，可疑时刻 ≤ 20。单次请求时间主要由一次
`n×n`（`n` = 两支探头读数总数）Cholesky 决定，候选时刻的秩一更新已批量向量化：
n = 2000、20 个候选时刻在本机单线程约 2.4 s。

覆盖：

## 六、设计决策与边界

- 选点新增点数固定为 2，枚举所有 C(m, 2) 点对精确评分，非贪心近似。
- 选点最小时间间隔只约束两个新采样点之间；与已测时刻的间隔通过「已测点排除 + 容差」处理。
- 核矩阵判定严格：零噪声下重复已测时刻直接判非正定；Cholesky 主元低于相对阈值
  （选点 1e-7、归因 1e-10）也判非正定，不做 jitter 修补——宁可整批拒绝也不给出
  数值上不可靠的建议。
- 归因中两支探头的噪声同方差但相互独立；阶跃只建模为“从 τ 起”的**常数**跳变，
  不含渐变/斜坡，因此对缓慢漂移不敏感（这类情形多半会给出“待复核”）。
- 阶跃角度的“共同/仅待检”比较的是两类**同一组数据**的边际似然：读数只有 7~10 对时
  “共同阶跃”的幅度先验可能吸收一部分整体曲线形状差异，导致先验质量偏向 H1；因此
  达到 90% 才下结论，读数较少时请补充数据而不是放宽阈值。
- 归因的“无阶跃”与两类阶跃比较的是**同一组读数**的边际似然；三类先验严格等权，
  时刻先验只在**有效**时刻间均分（无效时刻不占先验质量）。
